The repeatability dashboard measures your runs. How a harness changed itself

Every evolution recorded with a real agent. Each generation the harness tried at most one change and kept it only if a paired test over the tasks said it won more tasks than it lost. In the later evolutions, the tasks that moved ran again under both versions to see whether the win held. The agent's model is not named.

The hard six tasks, before and after the kept change

One square per run. The change was kept because one task moved, which a change that did nothing would do about half the time; so that task ran again under both versions, and the win held.

How strong the graders are

A task built from a repository's history is graded by the commit's own tests, held out from the agent. Small changes to the lines the commit changed (a flipped comparison, a constant one up, a negated condition) are graded by those tests; a change they miss is a gap in the tests, or a change that does nothing. Measured on this project's own recent commits.
